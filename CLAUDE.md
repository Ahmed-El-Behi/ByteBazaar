# CLAUDE.md — ByteBazaar

Online PC-parts store for Tunisia (prices in TND). UI, routes, commit messages and code comments are in **French**.
See `README.md` (setup, catalogue, security) and `backend/README.md` (data pipelines) for details.

## Stack

| Folder      | Tech                                                                 | Port |
| ----------- | -------------------------------------------------------------------- | ---- |
| `backend/`  | NestJS 12 · Prisma 7 (`prisma-client` generator, `@prisma/adapter-pg`) · PostgreSQL · Nodemailer | 3000 |
| `frontend/` | Angular 22 (standalone components, signals) · Three.js 0.186 · lucide (vanilla) | 4200 |

- Prisma config is `backend/prisma7.config.ts` → always pass `--config prisma7.config.ts` to Prisma CLI commands.
  Generated client lives in `backend/src/generated/prisma`.
- Env vars (`backend/.env`, template `.env.example`): `DATABASE_URL, JWT_SECRET, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, FRONTEND_URL, PORT`.
- Windows dev machine; `pg_dump` is at `C:\Program Files\PostgreSQL\18\bin\pg_dump.exe`. DB backups in `backend/backups/`.

## Commands

```bash
# backend
npm run start:dev            # API in watch mode
npm run seed                 # sync DB with both catalogue JSON files (idempotent, never overwrites stock)
npm run seed:stock           # reproducible test stock
npm run seed:demo-orders     # ~200 fake orders over 120 days for the dashboard (demo customers @demo.bytebazaar.test, idempotent, stock untouched)
npm test                     # unit tests (jest, ESM)   — 28+ tests, must pass
npm run test:e2e             # needs dev DB
npm run lint                 # oxlint — must be 0 warnings
npx tsc --noEmit -p tsconfig.json
npx prisma migrate deploy --config prisma7.config.ts

# frontend
npm start                    # ng serve (uses environment.development.ts)
npm run build                # production build — must succeed with no warnings (initial bundle < 500 kB)
npm test                     # Vitest (app.spec.ts, core/i18n.spec.ts)
npm run typecheck            # tsc, noUnusedLocals / noUnusedParameters enabled
npm run i18n:check           # 0 missing / 0 param mismatch
npm run format:check         # Prettier (npm run format to fix); backend is Prettier-clean too
```

**Working conventions**
- The user usually runs `ng serve` (4200) and the API in watch mode (3000) themselves — don't start servers on those ports; reuse them for browser checks.
- Commit / push only when the user asks. Work branch: `chore/nettoyage-catalogue-securite` (pushed to `origin`, no PR to `main` yet). Commit messages in French, conventional prefix (`feat:`, `chore:`…).
- Don't leave test data in the user's browser (e.g. the configurator build in `localStorage['bytebazaar_configurator']` — stash & restore it).
- Comments: only where they explain *why* (no banners, no restating the code). The `// i18n` … `// /i18n` and `// traduit à l'affichage` markers are functional (read by `check-i18n.mjs`) — keep them.
- `backend/.agents`, `backend/.claude`, `backend/.windsurf`, `backend/skills-lock.json` are generated by `prisma skills sync` (postinstall) and git-ignored.
- On Windows, bash heredocs mangle backslashes in Python/regex/JSON content — use the Write/Edit tools for such files.
- `prisma migrate dev --create-only` here may apply the migration and create a duplicate empty one — check `prisma/migrations/` afterwards.

## Architecture

### Backend (`backend/src`)
- `auth/` JWT auth, roles (`ADMIN` re-read from DB every request), password reset (15 min, single use, logs out sessions), rate-limit guard in `common/`.
- **Swagger + DTOs**: `/docs` (and `/api/docs` through the site; the proxies send `X-Forwarded-Prefix: /api` so « Try it out » targets the right base — `patchDocumentOnRequest` in `main.ts`). Every request body is a DTO class (`<module>/<module>.dto.ts`, `class-validator` + `@ApiProperty`); global `validationPipe` (`common/validation.ts`: `transform`, `whitelist`, `stopAtFirstError`, errors → `badRequest(...)` = `{ message: string[] }`). DTO messages use `msg(fr, en)` / `invalid(labelFr, labelEn)` and **must stay identical to the service messages** (same texts, same order); services keep their checks (defence in depth) and every business rule. Helpers: `Trim`, `TrimLower`, `ToNumber` (« 12 » → 12), `Optional` (skips undefined/null/« »), `IsCompleteAddress`. Shared constants live in the DTO files (`EMAIL_RE`, `PASSWORD_MIN/MAX`, `MAX_QUANTITY`, `PAYMENT_METHODS`, `ADDRESS_FIELDS`). Add `@ApiTags/@ApiOperation` (French) and `@ApiBearerAuth` on new routes.
- `catalog/` product list/detail, filters, sort; default sort **Pertinence** = `relevance.ts` (per-category popularity, daily-seeded randomness, availability; text match wins when searching).
- `cart/`, `order/`, `admin/`, `mail/`:
  - `order/order-status.ts` — **pure rules**, unit-tested: forward-only transitions (DELIVERED/CANCELLED final), customer may cancel while PENDING/CONFIRMED, CARD/PAYPAL are paid at checkout (simulated), cancelling a paid order → REFUNDED.
  - `order/order-cancel.ts` — `cancelOrderTx` (restock + RETURN stock movements + refund + event), shared by `POST /orders/:id/cancel` and the admin.
  - `OrderEvent` table = dated status history (who did it); every status change writes one. Migration `20261115120000_order_events` backfills existing orders from their dates.
  - E-mails (French only, Handlebars `strict`): `order-confirmation` at checkout, `order-status` on each change, both link to `/commandes/:id`. Failures are logged, never thrown.
  - `admin/dashboard.service.ts` — `GET /admin/dashboard?days=7|30|90|365`: KPIs with % change vs previous period, revenue timeline (days, or months for 365; Africa/Tunis calendar), statuses, payment methods, root-category sales, top products, low stock, recent orders. Revenue excludes cancelled orders.
- `configurator/`
  - `compatibility.ts` — **pure functions**, unit-tested. `CORE_SLOTS = cpu, motherboard, ram, gpu, storage, psu, case`; `OPTIONAL_SLOTS = cooler, monitor, keyboard, mouse, headset`. Checks: CPU↔motherboard socket, RAM DDR type ↔ motherboard, form factor ↔ case, GPU length, PSU wattage, cooling (missing cooler = *warning* only). A build is `complete` when all core slots are filled, no error/pending, and the only warnings are `cooling`. Peripherals never affect compatibility.
  - `configurator.service.ts` — `GET /configurator/parts?slot=&…selection` returns only parts compatible with the current selection (e.g. choosing a motherboard narrows CPUs to its socket, RAM to its DDR); `GET /configurator/check`; saved configurations CRUD under `/configurations`. Cooler info (`liquid`, `radiatorMm`) is derived from the "Radiator Size" spec or "AIO" in the name.
- `prisma/hardware.ts` — extracts structured hardware rows (`Cpu`, `Motherboard`, `Ram`, `Gpu`, `PowerSupply`, `PcCase`, `Monitor`, `Mouse`, `Keyboard`, `Headset`, `Speaker`, `Webcam`) from product specs; called by `seed.ts`.

### Data / catalogue (`backend/data`, `backend/scripts`)
- Sources of truth: `catalogue_local_images_cleaned.json` (≈3 000 components) + `accessories_catalogue.json` (894 peripherals). `seed.ts` merges both.
- Names are normalised to professional-retailer format by `scripts/normalize_catalogue.py` (original kept in `source.originalName`).
- Peripherals: `scripts/build_accessories.py` from `data/raw/pc-part-dataset/` (docyx/pc-part-dataset, MIT); photos matched strictly (brand + exact model + colour) by `scripts/match_accessory_images.py` against Amazon Reviews 2023 metadata (DuckDB), result in `data/raw/accessory_images.json`, downloaded by `download_product_images.py`. Only products with a photo are sold. Amazon dataset has no declared licence → educational use.
- Home hero showcase: `scripts/build_showcase.py` scores every local photo (resolution, white background, framing, contrast; monitors: bottom corners + colourful screen) and keeps the 15 most-reviewed products per featured category in `data/showcase.json`. `GET /products/showcase` draws 3 in-stock products from 3 different categories on each call (weights in `SHOWCASE_WEIGHTS`: GPU/monitors/keyboards/CPU/RAM first; never webcams or speakers). Re-run the script after changing the catalogue.
- Product images are local: `frontend/public/products/<category>/<SKU>.jpg` (accessories: `ACC-*.jpg` in `ecrans/ claviers/ souris/ casques/ enceintes/ webcams/`).

### Frontend (`frontend/src/app`)
- `core/` API services, guards, interceptor, `theme.service.ts` (light/dark), `tnd.pipe.ts`, `spec-labels.ts` (French labels for specs).
- `components/icon.ts` — `<app-icon name="…">` renders Lucide icons; use it for every icon (no emoji / hand-drawn SVG).
- Logo: `components/logo-mark.ts` (`<app-logo-mark>`) — pixel-grid « BB » (5×7 per letter, orange + cyan accent pixels) on a navy tile; one-time « boot » animation, accent glow on hover; used in header, footer, invoice. Favicons use the same drawing (`favicon.svg`, `favicon-dark.svg` = + light rim, `favicon.ico` 16/32/48, `apple-touch-icon.png` 180); their URLs carry `?v=2` (index.html + theme.service.ts) — bump it when the logo changes, browsers cache favicons hard.
- Content text is selectable; interface chrome is not (`button`, `.btn`, `nav`, `label`, `.pill`, `.badge`, tabs, icons, logo — `styles.css`), so quick clicks don't highlight anything. Values to copy (RIB…) also have a « Copier » button.
- Design tokens in `src/styles.css`: surfaces `--bg < --surface < --surface-2 < --surface-3`, `--text/--text-2/--muted`, `--accent`, `--font-display` + `--font-body`, scale `--fs-2xs … --fs-5xl`, radii `--r-*`, shadows `--shadow*`. Reuse tokens, don't hard-code colours/sizes.
- Routes are French (`/produits`, `/configurateur`, `/panier`, `/checkout`, `/compte/...`, `/conditions`, `/confidentialite`, `/admin/commandes`, `/admin/stock`). Every page is lazy (`loadComponent`) except Home and ProductList; titles are French and translated by `TranslatedTitleStrategy`.
- API base URL is `/api` (same origin) in both environments: `ng serve` proxies it via `proxy.conf.json`; `npm run serve` (`scripts/serve.mjs`, port 4300, brotli/gzip + cache headers) serves the production build and proxies it; in production a reverse proxy must forward `/api/*` (prefix stripped) to the API. `core/models.ts` exports `API_URL`.
- Mobile (≤640px): one-row header (logo + icon buttons; theme switch becomes a round button; Connexion/Inscription → user icon), swipeable nav row; 2-column product and category grids ≤560px. Touch devices: static ambient background; configurator starts in performance mode unless the user chose otherwise.
- Addresses are fully server-side: `GET/POST /orders/addresses`, `PATCH /orders/addresses/:id/default`, `DELETE /orders/addresses/:id` (deleting the default promotes the most recent one). The old localStorage workaround (`bytebazaar_deleted_addresses`, `bytebazaar_default_address_id`) is gone.
- Legal pages (`pages/legal.ts`, texts in `core/legal-content.ts`): seller identity placeholders must be completed before going live.
- Orders: `core/orders-api.ts` holds every order type, label map and `statusTone`/`paymentTone` (global `.pill .tone-*` classes in `styles.css`). Pages: `order-detail.ts` (`/commandes/:id`, `?nouvelle=1` after checkout: thank-you banner, `OrderTimeline`, bank details, cancel modal), `invoice.ts` (`/commandes/:id/facture` and `/admin/commandes/:id/facture` with `data.admin`; white A4 sheet, print CSS in `styles.css`), `account-orders.ts`. Store identity, bank details, `VAT_RATE` and `vatBreakdown` in `core/store-info.ts` (demo values).
- Performance (zoneless Angular: a template event listener re-runs change detection for the whole app):
  - Continuous pointer effects that only set CSS variables are bound with `addEventListener` (home hero/category halo, `pc-scene` hover, revenue-chart crosshair), never `(pointermove)` in templates.
  - `CatalogApi.categories()/brands()/categoryCovers()` are cached for the session (`shareReplay`).
  - `core/preloading.ts` (`IdlePreloading`): lazy pages are preloaded once the browser is idle, except `/admin*` (configurator: desktop only, later).
  - Home: infinite animations are paused (`.offscreen`) while their section is out of view (IntersectionObserver, 120px margin).
  - Catalogue brand list: `content-visibility: auto` with `contain-intrinsic-size` = the row's real content height (21.69px) so the scrollbar is unchanged.
  - `Icon` and `ProductCard` are OnPush. Images in lists: `loading="lazy" decoding="async"`.
  - Configurator 3D (`pc-scene.ts`, `pc-model.ts`, `three-merge.ts`) — all verified pixel-identical against the previous rendering:
    - `mergeStaticMeshes`: per part, static opaque meshes with equivalent materials are merged (≈368 → 190 meshes, 233 → 55 shadow casters). Kept separate: spinners, transparent, `userData`-flagged, mirrored meshes, `accentMats`.
    - Shadow map `autoUpdate = false`; `PcModel.shadowsNeedUpdate()` asks for a refresh only when a part moves/changes (install, hover lift, selection, quality) — or every frame while opaque (non-RGB) fan blades spin.
    - `setSelection` reuses a part whose `buildKey` (part id + layout, + mb/gpu presence for the PSU) is unchanged; same ids → no rebuild at all.
    - Anti-aliasing: the composer's HDR target uses MSAA 4×; if the median frame of the first ~2 s exceeds 20 ms (integrated GPU), it switches once to an `FXAAPass` (MSAA 2×/4× drops an Intel UHD to 40–48 fps, FXAA keeps 60). Canvas textures use anisotropy 16.
    - Never share a transparent `DoubleSide` material across many meshes without `forceSinglePass` (three.js flips `side` + `needsUpdate` twice per mesh per frame → program re-check each time; the fan-blade material cost ~15 % of the main thread), nor one material between an `InstancedMesh` and a plain mesh.
    - Render loop stops while the canvas is off-screen (IntersectionObserver). Programs are compiled with `compileAsync` against `composer.readBuffer` (bloom renders to a render target) before the first frame.
    - `localStorage['bytebazaar_configurator']` also stores `parts` so the full build is drawn at once on return visits (API check still refreshes it).
    - Picker: parts lists cached per slot+selection+language in `ConfiguratorApi`; cards rendered progressively (`FIRST_CARDS`, `CARDS_PER_FRAME`); images lazy.
    - Configurator chunk preloaded on intent (pointer/touch/focus on a `/configurateur` link, `app.ts`) and, on desktop only, by `IdlePreloading` after 5 s.
  - `scripts/serve.mjs` compresses every asset once at start-up (brotli 11 / gzip 9, cache keyed by mtime).
- Admin: `components/admin-nav.ts` tabs; `admin-dashboard.ts` (`/admin`) with `components/revenue-chart.ts` (SVG, crosshair + tooltip, arrow keys, screen-reader table); single chart hue `--viz-series` (validated with the dataviz skill). `admin-orders.ts`: search, filters with counts (`?filtre=a-traiter|virements`, `?ref=`), next-step buttons, mark paid, cancel, history. Phones: rows become cards.

### Languages (FR default / EN) — every user-facing text must exist in both
- Header toggle (`app.html`, `.lang-switch`) → `I18nService` (`core/i18n.ts`), saved in `localStorage['bytebazaar_lang']`, sets `<html lang>`.
- **Frontend**: texts stay written in French; the French text is the key. Templates: `{{ 'Texte' | t }}`, params `{{ '{n} produits' | t: { n: x } }}`, attributes `[title]="'Texte' | t"` (apostrophe in an attribute → `&quot;L'article&quot; | t`). Code: `translate('Texte')` / `i18n.t()`. English in `core/i18n-en.ts` (British English).
- Lists of labels kept in French (status maps, sort options…) are wrapped in `// i18n` … `// /i18n` comments and translated at display; signal values set in French and translated in the template get `// traduit à l'affichage`.
- `| localName` for categories (API `nameFr`/`nameEn`), `| productName` for product names (translates the final colour in brackets, e.g. « (Noir) » → « (Black) »), `| tnd` follows the locale (fr-FR / en-GB). Product page: `descriptionEn` and raw English specs in EN.
- **Check after any UI change**: `node scripts/check-i18n.mjs` (from `frontend/`) — must report 0 missing / 0 param mismatch.
- **Backend**: interceptor sends `Accept-Language: fr|en`; `common/i18n.ts` middleware (AsyncLocalStorage) → use `tr('texte FR', 'English text')` for every message returned to the UI (exceptions, compatibility checks, configurator highlights). The configurator re-fetches its check when the language changes.
- Not translated (out of the website): transactional e-mails (`mail/`) are French only.

### 3D configurator (`pages/configurator.ts` + `components/`)
- `pc-scene.ts` — Three.js scene (OrbitControls, RoomEnvironment, bloom post-processing, shadows). **Two modes**:
  - `desk` (default): desk with monitor/keyboard/mouse/headset + PC. The whole PC is a single hover target `'pc'` (deliberately low hover sensitivity); hovering a peripheral shows its card, click opens its picker.
  - `pc`: clicking the PC flies the camera in (1.1 s eased tween, controls disabled during flight); each component is hoverable (pops out) and clickable. "← Vue d'ensemble" button or Escape returns to desk.
  - Per-mode camera limits in `VIEWS` (target, radius, polar/azimuth ranges, distance).
- `pc-model.ts` — builds the case and components (`Builder`, `glowMesh` for RGB, `SlotView` with pop-out axis `z`/`y`), `hitTargets(mode)`, `slotOf(object, mode)`, `anchorOf`. Cooler: air tower or AIO (pump + RGB ring, tubes, radiator under top panel sized from `radiatorMm`; top case fans removed when AIO); ghost frame when empty.
- `screen-preview.ts` — the monitor's screen: the dark-theme home page in a browser window, drawn on a 2048-px canvas (texts via `translate()`; the monitor is rebuilt when the language changes).
- `desk-model.ts` — desk (`DESK_Y`, `DESK_TARGET`), monitor (size/aspect from specs, RGB strip if RGB or ≥144 Hz), keyboard (full/TKL/compact, instanced keys, RGB underglow), mouse, headset on stand; cables when wired.
- `three-utils.ts` — `isWhite`, `isRgb`, `productColor` (colour from the final parenthetical of the product name), `seeded`, `canvasTexture`.
- Slot lists on the frontend: `PC_SLOTS` / `DESK_SLOTS` in `core/configurator-api.ts`; chips grouped "Unité centrale" / "Poste de travail (facultatif)".
